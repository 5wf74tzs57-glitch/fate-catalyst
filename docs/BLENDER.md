# Editing Catalyst models in Blender

Every model in the game (cars, people, street props and catalysts) is a `.glb` file in `assets/`. The **Catalyst Asset Kit** add-on opens any of them in Blender with labels and helpers, checks your edits, and exports them straight back into the game.

Works with Blender 4.2 or newer, including 5.x.

## One-time setup

1. **Get the game folder onto your PC.** Unzip `Catalyst-BlenderKit.zip` somewhere permanent, for example `Documents\Catalyst`. (Or clone this repo.) The folder must contain `index.html` and `assets\`.
2. **Install the add-on.** In Blender: **Edit > Preferences > Add-ons**, then the **⌄** menu at the top right, then **Install from Disk…**. Pick `tools\blender\catalyst_kit.py` and tick the checkbox to enable **Catalyst Asset Kit**.
3. **Point it at the game.** In the add-on's preferences (or in the panel), set **Game folder** to the folder from step 1.
4. In the 3D viewport, press **N** and open the **Catalyst** tab.

If you just want to look around, open `tools\blender\Catalyst_Assets.blend`. It has one scene per asset, already set up. The add-on finds the game folder automatically when you open that file from inside the game folder.

## Editing an asset

1. **Pick an asset** from the dropdown and press **Open asset**. It opens in its own scene:
   - **FC_Asset** collection: the model itself. Everything in here gets exported.
   - **FC_Helpers** collection: a 1.75 m reference person, a **FRONT** arrow, the asset's title and notes, and a color legend. None of this gets exported, and none of it is selectable, so it stays out of your way.
2. **Model as usual.** Edit meshes, add parts (new objects you add go into FC_Asset), move things around.
3. **Paint colors** from the panel's **Paint** section. In Edit Mode it paints the selected faces; in Object Mode it paints whole objects. Use the marker colors for anything the game should recolor (see below).
4. Press **Check asset**. Errors block export; warnings are worth reading.
5. Press **Export to game**. The previous file is backed up to `assets\_backups\` (the last 10 per asset).
6. Press **Play in browser**. The add-on runs the game from your folder. After each export, refresh the browser tab to see the change.

**Reset to original** puts the shipped model back (your export stays in `_backups`).

## Conventions the game relies on

| What | Rule |
| --- | --- |
| Units | 1 Blender unit = 1 meter. |
| Facing | The game's **forward** is Blender's **−Y**: in Front view (numpad 1), cars and people face you. Follow the FRONT arrow. |
| Ground | Z = 0 is the street. Keep wheels and feet on it. |
| Root | Each asset has an empty named after it (`sedan`, `person`…) at the world origin. Export parents any loose objects to it. |
| Names | The game finds parts by name. `.001` suffixes are fine. |
| Colors | Vertex colors (preferred) or plain material colors. Image textures are ignored. |

### Hitboxes (red wireframes)

Objects whose names start with `HITBOX` are the physics shapes. The game reads the size and position of each one's bounding box, so scaling a hitbox in Blender changes how big the object is in the physics. Toggle them with **Hitboxes** in the panel.

### Marker colors

The game swaps these exact colors when it builds each car or person, so every car gets its own paint and every pedestrian their own outfit.

| Marker | Color | Used on |
| --- | --- | --- |
| Paint / Shirt | magenta `#FF00FF` | car body paint; a person's shirt and sleeves |
| Pants | cyan `#00FFFF` | a person's pants |
| Skin | yellow `#FFFF00` | a person's skin |
| Hair | green `#00FF00` | a person's hair |
| Shoes | blue `#0000FF` | a person's shoes |

Any other color stays exactly as you painted it. The taxi's yellow, Gary's whole look and every prop's colors are fixed.

## What each asset controls

| Asset | Parts the game looks for | What your edits change |
| --- | --- | --- |
| Sedan, Taxi, SUV, Delivery van | `body`, `HITBOX`, `HITBOX_cabin` (optional), `door` | Looks, physics box and roof box. `door` is the Car Door catalyst's door, and **its origin is the hinge**. |
| Log truck | the above plus `straps` and `log_slot_1`…`log_slot_5` | Where the logs sit, and the straps the scissors cut. |
| Pedestrian (`person`) | `torso`, `head`, `armL`, `armR`, `legL`, `legR`, each with a `HITBOX_<part>` child | Looks, ragdoll sizes, and **joints**: each part's origin is the joint it swings around. Moving an origin moves the joint. |
| Gary | the same six parts | Looks only. Gary bends at the pedestrian's joints. |
| Lamp post, hydrant, trash can, newspaper box, hot dog cart | `body`, `HITBOX` | Looks and physics box. |
| Skateboard, balls, bag, thumbtack, scissors, squirrel, bottle, cloud, log | any meshes | Looks only. Gameplay sizes are fixed in code, so keep them about the same size. |

Buildings, roads and trees are still generated by code. They'd be a good next asset kit.

## Getting your changes into the shared game

Your exports change the game on your PC right away. To put them in the online version and the Windows build, send the changed `.glb` files from `assets\` to Claude (drag them into the chat). Claude will commit them and rebuild. Or push them to the GitHub repo if you use Git.

## Troubleshooting

- **The panel says "Pick the folder with index.html".** The Game folder setting points at the wrong place. It's the folder that contains `index.html`, not `assets\`.
- **My change doesn't show up in the browser.** Refresh the tab. The game only picks up files when it's served from your folder through **Play in browser**. Opening `index.html` by double-clicking can't load model files.
- **The model is invisible or broken in game.** The game falls back to the built-in model if a file can't be used, and says why in the browser console (F12). Run **Check asset** and look for errors.
- **Colors look washed out in Blender.** In the viewport's Solid shading menu, set Color to **Attribute**. Open asset does this for you.
